# 封面结构与正文配图类型

风格决定视觉语言，结构决定第一眼如何阅读。每项资产只选一种。

## 封面结构

### single-hero 单一主体

一个产品、装置、物体或人物占据视觉中心。适合有明确可视对象的选题。要求：轮廓清晰，
背景只提供语境，缩略图中仍能认出主体。

### unfinished-moment 未完成瞬间

截取动作即将发生或刚发生的瞬间。适合人物故事与情绪观点。要求：动作、视线或道具形成
未完成叙事，不是摆拍。

### conceptual-tension 概念张力

用两个元素之间的尺度、材质、方向或空间矛盾表达核心观点。要求：冲突一眼可见，隐喻
一句话能解释，不堆砌象征物。

### system-landscape 系统景观

把流程或系统压缩成可读的空间场景：工作台、装置剖面、控制中心。封面只暗示系统，细节
留给正文。要求：场景中有一个可解释的入口、缺口、连接或重组关系。

### title-space 标题留白

短标题与一个克制主体共享版面，适合标题本身有冲击力、走 `short-exact` 路线时使用。
要求：文字与主体互相成就而非简单叠加。

### evidence-collage 证据拼贴

用少量文件、实物、截图的"类素材"建立证据感。要求：一个证据为主；素材全部无字或仅
抽象排版；不得使用真实文件复刻。

### 选择顺序

1. 有明确可视主体 → single-hero
2. 人物/故事推动 → unfinished-moment
3. 核心是冲突或悖论 → conceptual-tension
4. 解释复杂流程/系统 → system-landscape
5. 短标题本身有冲击 → title-space
6. 可信度来自文件/资料 → evidence-collage

## 正文配图

### 密度

| 密度 | 数量 | 适用 |
|---|---:|---|
| minimal | 1-2 | 短文、单一观点 |
| balanced | 3-5 | 默认 |
| per-section | 每个主要章节 ≥1 | 长文、结构化报告 |
| rich | ≥6 | 用户明确要求 |

短文或单一观点不按固定数量凑图。段落已经讲清楚的内容不重复做成装饰图；说不清单张图
具体作用的，删掉。

### 类型

| 类型 | 回答的问题 |
|---|---|
| overview-map | 整篇文章在讲什么（意象化的模块关系，不是精确框图） |
| process-path | 事情如何发生（顺序、转折、结果） |
| contrast-view | 两边差在哪里（用文章里的真实对照维度） |
| framework-model | 文章的框架/模型如何组成 |
| timeline | 关键时间节点如何演变 |
| evidence-card | 哪些事实材料支持观点（无字类文件） |
| scene-anchor | 读者应感受到什么处境（具体场景，不扛复杂信息） |
| data-anchor | 数据信号长什么样（盘面、设备、抽象图形；**不是**带精确坐标的图表） |

精确数据图表超出 AI 生图能力：模型无法保证坐标与数字准确，不允许用生成图冒充数据图。

### 每张图的规划字段

```text
位置：章节与对应段落
读者问题：在这里读者最可能不理解什么
图像答案：这张图怎样回答
类型：从上表选择
连续性：沿用封面的哪些主色、材质、镜头语言，做什么简化
```

同一结构不机械重复到全部章节：连续性来自视觉基因，变化来自信息功能。

# 手机端节奏与文案规程（量化吃瓜）

目标是完成率与转发：在微信推荐机制里，读完率比打开率更决定一篇文章能不能被继续推。
本文件只管"怎么写得让人读下去"；事实纪律不变——交叉验证、反方事实、口径标注、
不编造数字与经历，一条不让步。冷静不站队的账号人格也不变，节奏服务证据，
不服务情绪煽动。

## 1. 开头：三句之内给钩子

三种合规钩子，任选其一：

- **反直觉判断**：先抛一个与热搜直觉相反的结论，再解释。
- **说法 vs 数据**：热搜上的说法一句带过，立刻给出数据锚点（iPhone 篇式）。
- **具体处境提问**：读者下次站在货架前真会遇到的问题。

禁止"X月X日，XX冲上热搜。起因是……"式裸开——日期与背景放到钩子之后。
开头约200字内不加粗、不放框、不放图，先让读者顺滑进入。

## 2. 段落：为手机屏写

- 手机端每行约16–18字，一屏约10行。**常态段落≤80字（约4行），硬上限约120字。**
- 一段只推进一个事实或一个判断；两件事就拆成两段。
- 关键数字单独成句、尽量单独成段，让数字本身被看见。
- 长句拆短，每段以1–3句为主。

## 3. 节奏：长短交替加转弯

- 每300–500字安排一次节奏变化：一个一两句的短段、一次转折，或一张视觉卡。
- 转折词可用：但、问题是、有意思的是、换个角度、另一面是。
- "但是"式转弯每篇至少3次：先承认一方，再翻到另一方——"两派都有证据"
  天然需要这种结构。
- 禁用转场词（机械分扣分）：首先、其次、最后、此外、另外、事实上、可以说。

## 4. 金句：每篇2–4句

四种好用的句式：

1. 对比反转（"不是……而是……"）
2. 平行递进（"成本是第一位的选择，风味故事在其后"）
3. 悖论（"糖没有消失，只是不再需要写出来"类）
4. 短促断言。

写完自问：哪句话读者会划线、会转发？答不上来就重写。
其中1–2句用 `:::pullquote` 承载（居中金句卡）；金句要稀缺，不要句句加卡。

## 5. 视觉节奏：每1–2屏一个停顿元素

| 语法 | 用途 |
|---|---|
| `:::highlight` | 关键数字卡（第一行标题，第二行说明） |
| `:::summary` | 结论卡 / 口径卡 |
| `:::pullquote` | 金句卡 |
| `:::label` / `:::label pill` | 小节小标签 |
| `:::steps` | 读者行动清单，一条一步 |
| `:::timeline` | 时间线 |
| `:::callout info` | 数据口径与核验披露，每篇必有 |

1500–2000字的文章用3–5个文内元素即可，不堆砌；元素与元素之间用短段连接。
`:::` 后允许空格，`::: callout info` 与 `:::callout info` 都能正确渲染。

## 6. 加粗与颜色

- 加粗全篇≤5处，只给真正的数字锚点和结论，不给形容词。
- 颜色由主题统一（蓝灰为骨、琥珀点睛），正文不自行加色。
- ≥4字的中文括号注释全篇≤3个，否则机械分 insertion_control 项归零；
  长口径改写进 callout，而不是塞括号。

## 7. 收尾：给动作，轻收

- 结尾给读者能立即执行的动作，优先用 `:::steps` 承载。
- 最后一句留给有余味的判断或画面。不升华、不号召、不当人生导师。

## 交付前自检

- [ ] 前三句有钩子？日期背景没有抢在钩子前面？
- [ ] 有没有超过120字的段落？有就拆。
- [ ] 2–4句金句写出来了？其中1–2张 pullquote？
- [ ] 全文3–5个视觉停顿元素？
- [ ] 至少3次转折，长短段交替？
- [ ] 加粗≤5处、长括号≤3个、禁用转场词为零？
- [ ] 收尾给了动作，最后一句有余味？
- [ ] 事实、口径、反方、披露 callout 一项不少？
